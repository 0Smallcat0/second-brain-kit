# 參考：外部資源

> **給負責配置的 Claude 參考，不是必做。** 預設只有一個 Claude 帳號，其他都不用。這是完整款的一部分（[進階功能.md](進階功能.md) 的 A5）。「外部資源」指這個 Claude 帳號以外，使用者有的一切：其他 AI、運算、點數與服務。**這裡不替任何資源固定角色：** 模型一直在變強、變便宜，所以套件只給一條規則和工作的種類；哪個資源做哪種工作，寫在使用者自己的表（`~/.sbk/channels.md`），由他的 Claude 安裝時照他勾的項目填，每個月或有新模型出來時重新測試。經驗只讀使用者「有」的那幾個。每一條都是 2026 年在一個人的環境裡實際量過、或實際出過錯的；要靠它之前請重新量。

## 外部資源：一張表

安裝時用一題讓使用者勾這張清單（SETUP 步驟 0.2）。只有勾了的才寫進 `channels.md`；沒勾的一律不假設他有。標「可免費申請」的只當提醒；使用者說要，Claude 才教怎麼註冊。

| 類型 | 例子 | 多了什麼 | 免費註冊 |
|---|---|---|---|
| 其他 AI | 第二個 Claude 帳號、Codex（ChatGPT 方案）、ChatGPT 網頁版、Gemini 網頁版、Antigravity、Gemini API、OpenRouter | 另一份額度；一個沒看過你方案的模型 | ChatGPT 網頁版、Gemini 網頁版：可免費申請 |
| 運算 | Colab、Kaggle notebook、自己的 GPU | 跑重工作的 GPU 或執行環境，和自己的電腦平行 | Colab、Kaggle：可免費申請 |
| 點數與服務 | Azure for Students、GitHub Copilot（學生方案）、API 點數 | 雲端執行環境、另一個寫程式的模型、照用量付費的呼叫 | Azure for Students、學生版 Copilot：學生可免費申請 |

## 一條規則

**依工作種類，從使用者有、還有額度的資源裡挑現在最好的；交給它一份任務說明檔、收回一個檔，自己打開那個檔看。** 下面幾點都從這條來：

1. **依工作種類分工，不依「失敗」分工。** 事先決定哪種工作交給誰。不要做「帳號 A 到上限就悄悄改用 B」：一般消費者條款禁止繞過用量上限，也會讓你看不出真正用了多少。
2. **在派工的地方顯示狀態。** 可能被額度鎖住的資源（Antigravity、Codex），在 `~/.sbk/channels.md` 寫一行：資源、用途、鎖到何時；派工前先看。默默停住的佇列比沒有佇列更糟。
3. **交一份任務說明檔、收一個檔。** 每個工作都是一份任務說明檔（目標、輸入的完整路徑、輸出路徑、不做什麼、你怎麼驗收）；結果是你自己打開的檔，不信對方說「做完了」（見 `evidence-before-done`）。
4. **個資只留在你信任的資源上。** 免費額度和第三方轉接，只做不含密碼、不含私人紀錄、公開貼出也無妨的工作。
5. **現在最好，不是固定。** 不要把某個模型綁死在某種工作上：有更好或更便宜的模型出來時，改的是表，不是規則。
6. **獨立複查要盲問。** 定方向之前，其他模型只看需求和事實，不看 Claude 的方案或傾向，再比較。先給方案，盲點就已經跟著帶進複查裡了。

## 只有一個 Claude 帳號時

沒有外部資源是常態。工作照樣分種類，在同一個帳號裡分：
- **機械批次：** 交給用較便宜 Claude 模型（例如 Haiku）、低 effort 的子代理，附任務說明檔。
- **獨立複查：** 開一個新的子代理，只給需求、事實和做好的成品，不給原本的答案，也不給產生它的那段對話。
- **大量運算：** 只用使用者勾了的（自己的 GPU、Colab、Kaggle）；都沒有就直接說這台電腦跑不動，提議縮小的版本。

## 工作的種類

這裡只有通用規則。「現在交給哪個工具」寫在使用者的 `channels.md`。

| 工作種類 | 例子 | 現在哪個資源最適合，看這些 |
|---|---|---|
| 機械批次 | 搬檔改名、批次修改、掃描比對、跑腳本等結果、上傳再讀回 | 照任務說明檔做得準；每件最便宜；額度獨立，不拖慢主對話。用低 reasoning effort。 |
| 判斷 | 決定、要給別人看的文字、難的除錯、個人的事 | 使用者有的最強模型，帶著對話的脈絡，而且是可以放私人資料的帳號。 |
| 長篇閱讀 | 一堆論文或紀錄、很長的逐字稿、從大量文字起草 | 上下文最長、每個 token 便宜、還有額度的；私人資料只給信任的帳號。 |
| 大量運算 | 訓練、算圖、大批資料 | 有空的 GPU 或執行環境；第二台機器是拿來平行多跑，不是跑得更快。 |
| 獨立複查 | 對方向的第二意見、檢查做好的成品 | 另一個模型（最好是別家公司的），沒看過你的方案：只給需求和事實。 |

## 填表與重新檢查

- **安裝時（A5）：** 使用者勾的每一個資源，在〈使用者有的〉加一列（類型、資源、方案、怎麼呼叫、限制），跑一個很小的真實工作測過。再對每一種工作，在 `channels.md` 寫上現在最適合的資源，附一句理由和今天的日期。沒有外部資源的那一種就留在 Claude（見〈只有一個 Claude 帳號時〉）。只寫使用者勾的。
- **每個月（完整款：提醒列 `T01 | monthly 1 10:00 | maintenance | ...`），以及使用者說有新模型出來時：** 系統維護對話用一個很小的工作把每個資源重測一次，並逐列重新檢查——使用者每個資源現在提供什麼（看各家官方的模型與價格頁）、有沒有更新的模型做這種工作更好或更便宜、哪些帳號還在、還有額度——更新有變的列，追蹤表那一項附上看了什麼再關。
- **派工時：** 讀那一種工作的那一列，看「鎖到何時」；那個工具被鎖或沒額度，就刻意改用次好的，並說出來。不默默換。

## 各資源的經驗

2026 年在一個環境裡量到或遇到的。這些是工具的脾氣，不是角色：哪個工具「適合」什麼，每次新模型出來都會變，要用上面的表來決定。

## 第二個 Claude 帳號（額度池）

- **多了什麼：** 你合法擁有的第二份額度（例如第二個訂閱），拿來跑背景工作，讓主帳號留給對話。
- **交給它：** 有清楚任務說明檔的長背景工作（研究、批次修改、批次檢查）。
- **做法：** 用 `entry/worker.ps1`（Windows）或 `entry/worker.sh`，指定第二個帳號的設定資料夾。啟動腳本會把 `CLAUDE_CONFIG_DIR` 設成那個資料夾，並清掉 `CLAUDE_CODE_OAUTH_TOKEN` 和 `ANTHROPIC_API_KEY`；這兩個變數只要留著就會蓋過登入，工作會悄悄用錯帳號。每個帳號先登入一次：用那個 `CLAUDE_CONFIG_DIR` 啟動 `claude` 並執行 `/login`。
- **經驗：**
  - 依工作分工，不要在到上限時自動切換（共通規則 1）。
  - hook 依設定資料夾分別讀用量，所以每個帳號各有各的提醒。
  - 大半閒置的額度池是浪費：規劃大工作前兩邊的週用量都看一下，長背景工作放在有餘裕的那邊。

## Claude in Chrome（瀏覽器擴充功能）

- **多了什麼：** 用使用者真實的瀏覽器和登入狀態操作網頁。
- **經驗：**
  - 它屬於擴充功能登入的那個帳號；用別的帳號跑的工作就用不到它。
  - 環境裡有 token（`CLAUDE_CODE_OAUTH_TOKEN`，由 `claude setup-token` 產生）時，`claude -p` 會停用它。要用瀏覽器的工作必須加 `--chrome`，而且不能帶那個變數（`worker.ps1 -Chrome`）。
  - 自動化的瀏覽器工作會留下分頁和視窗越堆越多。每個瀏覽器工作結尾都寫「關掉自己開的，原本開著的不動」，之後自己數一次分頁。

## Codex CLI（ChatGPT 訂閱或 API 金鑰）

- **2026 年用來做過：** 機械工作（搬檔改名、批次修改、掃描比對、跑腳本等結果、上傳再讀回），以及沒看過你對話的新眼光檢查。
- **做法：** 唯讀檢查用 `codex exec --sandbox read-only --skip-git-repo-check "<任務說明檔或需求>"`；一定要寫檔的工作才拿掉 `--sandbox read-only`，並在任務說明檔裡寫明目標資料夾。機械工作用低 reasoning effort（更快，也少用很多額度）。
- **限制：** 有 5 小時視窗和每週上限。排大批工作前先看，碰到上限就把鎖定時間寫進 `channels.md`。
- **經驗：**
  - 不要在前景用迴圈輪詢它；啟動後去做別的事，再讀結果檔。
  - 結果自己打開看；工具說「完成」不是證據。
  - 判斷類工作（決定、給別人看的文字、難的除錯）交給分工表「判斷」那一列寫的工具，不是剛好在跑的這個。

## Gemini：網頁、Antigravity、API

- **網頁版（免費）：** 第二意見，要盲問（共通規則 6）。
- **Antigravity（內建 Gemini 代理的 IDE）：**
  - 2026 年用來做過超長閱讀和初稿，不花 Claude 額度。用共用資料夾裡的任務說明檔交辦，再讀它寫出的結果檔。
  - 額度用完可能鎖大約 6 天，這段時間佇列停住也不會報錯。把鎖定時間寫在派工的地方（`channels.md`），送任何東西前先看；被鎖就刻意改派別處。
- **Gemini API（用多少付多少）：**
  - 最後才用。失敗的呼叫也可能留著預留額度，算進預算。
  - 曾經把同一張大表重複送了 7 次以上，用掉大約半個月的預算。只送自上次以來有變的部分；穩定的部分放在檔案裡引用。
  - 第一次呼叫前先在帳戶上設花費上限。

## Colab、Kaggle 或本機 GPU

- **多了什麼：** 在你自己的 GPU 之外，多一張平行跑的 GPU。
- **經驗：**
  - 免費的 T4 並沒有比筆電的 RTX 4060 快（同一個模型，118 對 103.5 毫秒／步）。Colab 的價值是同時多跑一個工作，不是把一個工作跑得更快。
  - 閒置的 runtime 大約 80 分鐘後斷線，`/content` 裡的東西全部消失。一開始就把檢查點和輸出寫到 Google Drive，人離開前先複製結果回來。
  - 執行腳本和資料都放在 Drive，新的 runtime 才能接著跑。
  - Kaggle notebook 每週有 GPU 時數；排工作前先看帳號頁剩幾小時（這個環境沒量過）。

## OpenRouter 免費模型

- **2026 年用來做過：** 不含個資的機械文字工作（改格式、公開文字分類、公開網頁的初步摘要），量大時。
- **絕對不送：** 密碼、私人紀錄、不想公開的任何東西。免費額度可能會記錄提示內容。
- **經驗：** 免費模型常換、也會消失；把模型名稱寫進任務說明檔，排大批工作前先確認它回得出來。輸出用抽樣驗證。

## 小型本機模型

- 便宜又私密，但算數和精確記帳不可靠：一個小型本機模型把一個簡單的日誌統計數錯了（9，正確是 26）。只拿來粗略分類，精確的計數用腳本。

## 網頁版 ChatGPT／Gemini 當第二意見

- 免費、兩分鐘。把需求和事實寫成一個檔，不透露你自己的答案，請它提方案；和你的比較，不同的地方先弄清楚為什麼，再選。用在定方向，不用在日常工作。

## Azure for Students、Copilot、API 點數

- 這個環境沒量過。和其他列一樣處理：先跑一個很小的真實工作，把剩下的點數或上限寫進 `channels.md`，第一次付費呼叫前先設花費上限。

## 啟用一個資源（給配置的 Claude）

只對使用者勾了的資源做：
1. 在 `~/.sbk/channels.md` 的「What the user has」加一行：類型、資源、帳號或方案、怎麼呼叫、限制或「鎖到何時」（一開始留空）。
2. 填「Kind of work -> resource now」的每一種工作（見「填表與重新檢查」）；沒有更適合的資源，那一種就留在 Claude。
3. 實際跑一個最小的工作做到底（一份要求把一行字寫進檔案的任務說明檔），打開那個檔。看過才告訴使用者它能用，並在「tested on」寫上日期。
4. 完整款：`alarms.md` 留著每月重新檢查那一列 `| T01 | monthly 1 10:00 | maintenance | Re-check the outside resources table (channels.md): only what the user has |`（沒有 `alarms.md` 就從模板建）。

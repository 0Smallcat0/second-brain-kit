# 參考：多工具分工

> **給負責配置的 Claude 參考，不是必做。** 預設只有一個 Claude 帳號，其他都不用。只讀使用者說「有」的那幾個工具的章節（問題見 [SETUP](SETUP.md)）。這裡每一條都是實際量過、或實際出過錯的經驗；數字來自一個人的環境，要靠它之前請重新量。

## 所有額外工具共通的規則

1. **依工作類型分工，不依「失敗」分工。** 事先決定哪種工作交給誰。不要做「帳號 A 到上限就悄悄改用 B」：一般消費者條款禁止繞過用量上限，也會讓你看不出真正用了多少。
2. **在派工的地方顯示狀態。** 可能被額度鎖住的工具（Antigravity、Codex），在 `~/.claude/sbk/channels.md` 寫一行：工具、用途、鎖到何時；派工前先看。默默停住的佇列比沒有佇列更糟。
3. **交一份 brief、收一個檔。** 每個工作都是一份 brief 檔（目標、輸入的完整路徑、輸出路徑、不做什麼、你怎麼驗收）；結果是你自己打開的檔，不信對方說「做完了」（見 `evidence-before-done`）。
4. **個資只留在你信任的工具上。** 免費額度和第三方轉接，只做不含密碼、不含私人紀錄、公開貼出也無妨的工作。
5. **機械工作給便宜的，判斷留給 Claude。** 搬檔、掃描、跑腳本等結果、排版、批次修改：交出去。決定、要給別人看的文字、難的除錯：自己留著。
6. **第二意見要盲問。** 想聽另一個模型對方向的看法，只給需求和事實，不給自己的方案或傾向，再比較；否則它多半會附和你。

## 哪種工作交給誰

| 工作類型 | 首選 | 原因 |
|---|---|---|
| 短問題、個人事務、最後的措辭、決定 | Claude（主帳號） | 你有脈絡；隱私 |
| 機械批次、跑腳本、獨立的新眼光檢查 | Codex CLI（有的話） | 便宜、額度獨立 |
| 超長閱讀、從一大堆文字起草 | Antigravity／Gemini（有的話） | 省主帳號額度 |
| 同一工作在另一台機器／GPU 上也跑 | Colab（有的話） | 多一份平行算力，不是更快 |
| 不含個資、量很大的機械工作 | OpenRouter 免費模型（有的話） | 免費 |
| 有實際後果的方向或決定 | Claude＋一次網頁版盲問 | 補盲點 |

## 第二個 Claude 帳號（額度池）

- **適合：** 你合法擁有的第二份額度（例如第二個訂閱），拿來跑背景工作，讓主帳號留給對話。
- **交給它：** 有清楚 brief 的長背景工作（研究、批次修改、批次檢查）。
- **做法：** 用 `entry/worker.ps1`（Windows）或 `entry/worker.sh`，指定第二個帳號的設定資料夾。啟動腳本會把 `CLAUDE_CONFIG_DIR` 設成那個資料夾，並清掉 `CLAUDE_CODE_OAUTH_TOKEN` 和 `ANTHROPIC_API_KEY`；這兩個變數只要留著就會蓋過登入，工作會悄悄用錯帳號。每個帳號先登入一次：用那個 `CLAUDE_CONFIG_DIR` 啟動 `claude` 並執行 `/login`。
- **經驗：**
  - 依工作分工，不要在到上限時自動切換（共通規則 1）。
  - hook 依設定資料夾分別讀用量，所以每個帳號各有各的提醒。
  - 大半閒置的額度池是浪費：規劃大工作前兩邊的週用量都看一下，長背景工作放在有餘裕的那邊。

## Claude in Chrome（瀏覽器擴充功能）

- **適合：** 用使用者真實的瀏覽器和登入狀態操作網頁。
- **經驗：**
  - 它屬於擴充功能登入的那個帳號；用別的帳號跑的工作就用不到它。
  - 環境裡有 token（`CLAUDE_CODE_OAUTH_TOKEN`，由 `claude setup-token` 產生）時，`claude -p` 會停用它。要用瀏覽器的工作必須加 `--chrome`，而且不能帶那個變數（`worker.ps1 -Chrome`）。
  - 自動化的瀏覽器工作會留下分頁和視窗越堆越多。每個瀏覽器工作結尾都寫「關掉自己開的，原本開著的不動」，之後自己數一次分頁。

## Codex CLI（ChatGPT 訂閱或 API 金鑰）

- **適合：** 機械工作（搬檔改名、批次修改、掃描比對、跑腳本等結果、上傳再讀回），以及沒看過你對話的新眼光檢查。
- **做法：** 唯讀檢查用 `codex exec --sandbox read-only --skip-git-repo-check "<brief 或需求>"`；一定要寫檔的工作才拿掉 `--sandbox read-only`，並在 brief 裡寫明目標資料夾。機械工作用低 reasoning effort（更快，也少用很多額度）。
- **限制：** 有 5 小時視窗和每週上限。排大批工作前先看，碰到上限就把鎖定時間寫進 `channels.md`。
- **經驗：**
  - 不要在前景用迴圈輪詢它；啟動後去做別的事，再讀結果檔。
  - 結果自己打開看；工具說「完成」不是證據。
  - 判斷類工作（決定、給別人看的文字、難的除錯）留給 Claude。

## Gemini：網頁、Antigravity、API

- **網頁版（免費）：** 第二意見，要盲問（共通規則 6）。
- **Antigravity（內建 Gemini 代理的 IDE）：**
  - 適合超長閱讀和初稿，不花 Claude 額度。用共用資料夾裡的 brief 檔交辦，再讀它寫出的結果檔。
  - 額度用完可能鎖大約 6 天，這段時間佇列停住也不會報錯。把鎖定時間寫在派工的地方（`channels.md`），送任何東西前先看；被鎖就刻意改派別處。
- **Gemini API（用多少付多少）：**
  - 最後才用。失敗的呼叫也可能留著預留額度，算進預算。
  - 曾經把同一張大表重複送了 7 次以上，用掉大約半個月的預算。只送自上次以來有變的部分；穩定的部分放在檔案裡引用。
  - 第一次呼叫前先在帳戶上設花費上限。

## Colab 或本機 GPU

- **適合：** 在你自己的 GPU 之外，多一張平行跑的 GPU。
- **經驗：**
  - 免費的 T4 並沒有比筆電的 RTX 4060 快（同一個模型，118 對 103.5 毫秒／步）。Colab 的價值是同時多跑一個工作，不是把一個工作跑得更快。
  - 閒置的 runtime 大約 80 分鐘後斷線，`/content` 裡的東西全部消失。一開始就把檢查點和輸出寫到 Google Drive，人離開前先複製結果回來。
  - 執行腳本和資料都放在 Drive，新的 runtime 才能接著跑。

## OpenRouter 免費模型

- **適合：** 不含個資的機械文字工作（改格式、公開文字分類、公開網頁的初步摘要），量大時。
- **絕對不送：** 密碼、私人紀錄、不想公開的任何東西。免費額度可能會記錄提示內容。
- **經驗：** 免費模型常換、也會消失；把模型名稱寫進 brief，排大批工作前先確認它回得出來。輸出用抽樣驗證。

## 小型本機模型

- 便宜又私密，但算數和精確記帳不可靠：一個小型本機模型把一個簡單的日誌統計數錯了（9，正確是 26）。只拿來粗略分類，精確的計數用腳本。

## 網頁版 ChatGPT／Gemini 當第二意見

- 免費、兩分鐘。把需求和事實寫成一個檔，不透露你自己的答案，請它提方案；和你的比較，不同的地方先弄清楚為什麼，再選。用在定方向，不用在日常工作。

## 啟用一個工具（給配置的 Claude）

只對使用者有的工具做：
1. 在 `~/.claude/sbk/channels.md` 加一行：工具、用途、怎麼呼叫、「鎖到何時」（一開始留空）。
2. 把這個工具適合的工作類型，用一句話寫進會用到它的主題對話 `task.md` 的 Rules 區。
3. 實際跑一個最小的工作做到底（一個把一行字寫進檔案的 brief），打開那個檔。看過才告訴使用者它能用。

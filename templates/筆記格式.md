# Note format

Folder and file names are in the user's language; the rules below are for the AI working here.

## 1. Folder numbers (JDex)

Three levels: area -> category -> note.

```
20-29 學習與讀書/            <- area: ten numbers per area, folder name "first-last name"
  21 課程/                   <- category: two digits, folder name "NN name"
    21-03 線性代數.md        <- note: "category-running number title.md"
```

The areas below are **examples** (範例). At setup Claude proposes this user's areas from their answers (student, office worker, freelancer..., what they use Claude for), creates them only after the user confirms, and replaces this table with their areas. At first only `00-09`, the one or two areas the user uses, and `90-99` exist; other areas are created when the first note needs them:

| Area (範例) | What goes there |
|---|---|
| 00-09 系統與索引 | 00 index, 01 rules (this note), 02 inbox, 03 和 AI 協作 (corrections and confirmations) |
| 10-19 自己與生活 | journal and reviews, habits, goals |
| 20-29 學習與讀書 | courses, reading notes, exams and assignments |
| 30-39 工作與打工 | work records, skills and CV material |
| 40-49 專案 | side projects, ideas |
| 50-59 人際與社團 | clubs, friends and contacts |
| 60-69 金錢與行政 | income and spending, accounts and documents |
| 70-79 興趣與娛樂 | hobbies, lists |
| 80-89 參考資料 | articles and links, tools and settings |
| 90-99 封存 | 91 finished projects, 92 outdated notes |

Rules:
- The category number always matches the folder's number: every note in `21 課程` is named `21-NN ...`.
- A new note takes the category's "next free number" from the JDex index; never skip or reuse numbers.
- Categories are opened when needed; when one gets too full, split it in two instead of piling up dozens of notes.
- File names never contain these characters: `: * ? " < > | # ^ [ ]`.

## 2. Frontmatter

At the top of every note:

```yaml
---
type: skill
status: active
summary: one sentence saying what this note is
created: 2000-01-31
modified: 2000-01-31
origin: user
---
```

| Field | Values |
|---|---|
| type | profile (about me), preference, skill (know-how), person, event, area (long-running), project (has an end), idea, daily (journal), moc (index page), log (running record), reference |
| status | active, review (to be confirmed), done (finished, kept), someday, archived |
| summary | one sentence; the JDex and search depend on it; never empty |
| created / modified | `YYYY-MM-DD`; when the content changes, set modified to today |
| origin | user (the user said it), agent-drafted (drafted by AI), agent-inferred (AI guess, to be confirmed), book, research (looked up), mixed |

Optional: `tags`, `aliases`, `end_date` (project end), `valid_until` (when the information goes stale; lint warns after it).

A link inside frontmatter needs the whole value in quotes: `related: "[[21-03 線性代數]]"`, otherwise the YAML breaks.

## 3. Links and body

- Link notes with `[[file name]]` (without .md); images with `![[image.png]]`. A link to a note that does not exist is a lint ERROR.
- One note, one subject; split it above 500 lines.
- To-dos are `- [ ]` followed by a date; lint warns when one sits too long.
- An uncertain fact is written as "to be confirmed" with origin `agent-inferred`, never as certain.
- `origin` keeps "the user said" apart from "the AI inferred": AI text does not become the user's words by being saved in a note.

## 4. Retiring a note = moving it to the archive

- A note no longer used: `status: archived`, moved to `90-99 封存`. Never deleted.
- Every note in the archive has status archived, and the other way round; lint checks it.

## 5. The root folder

The root holds only `AGENTS.md`, `CLAUDE.md` (one line: `@AGENTS.md`) and `README.md`. Every other note belongs in a category.

## 6. Generated and protected

| What | Written by | May it be changed |
|---|---|---|
| `00 索引/00-01 JDex 索引.md` | `scripts/gen_jdex.py`, automatically | never by hand |
| This format note, `AGENTS.md`, `CLAUDE.md` | the user and the AI together | ask the user first |
| `scripts/` | this kit | ask the user first |
| Other notes | anyone | change only what must change |

## 7. Checks

```
python scripts/vault_lint.py          # ERROR must be 0; handle or explain each WARN
python scripts/gen_jdex.py            # refresh the index
```

On commit, `scripts/pre-commit` runs by itself: it stops a whole note from being wiped and runs the lint on what is being committed.

# 筆記格式

## 1. 資料夾編號（JDex）

三層：區（Area）→ 類別（Category）→ 筆記。

```
20-29 學習與讀書/            ← 區：十個號碼一區，資料夾名「起-訖 名稱」
  21 課程/                   ← 類別：兩位數，資料夾名「NN 名稱」
    21-03 線性代數.md        ← 筆記：「類別號-流水號 標題.md」
```

可用的區（可改名、可不用）。一開始只建 `00-09`、使用者常用的一兩個區、`90-99`；其他區第一次有筆記要放時才建：

| 區 | 放什麼 |
|---|---|
| 00-09 系統與索引 | 00 索引、01 規則（就是這張）、02 收件匣 |
| 10-19 自己與生活 | 日記與回顧、習慣、目標 |
| 20-29 學習與讀書 | 課程、讀書筆記、考試與作業 |
| 30-39 工作與打工 | 工作紀錄、技能與履歷素材 |
| 40-49 專案 | side project、點子 |
| 50-59 人際與社團 | 社團、朋友與人脈 |
| 60-69 金錢與行政 | 收支、帳號與文件 |
| 70-79 興趣與娛樂 | 興趣、清單 |
| 80-89 參考資料 | 文章與連結、工具與設定 |
| 90-99 封存 | 91 已結束專案、92 過期筆記 |

規則：
- 類別號一定要和資料夾的號碼一致：`21 課程` 裡的筆記都叫 `21-NN …`。
- 新筆記用 JDex 索引裡該類別的「下一個空號」，不要跳號重用。
- 類別是在需要時才開；一個類別放不下就拆成兩個，不要塞到幾十張。
- 檔名不用這些字元：`: * ? " < > | # ^ [ ]`。

## 2. Frontmatter

每張筆記最上面：

```yaml
---
type: skill
status: active
summary: 一句話說這張筆記是什麼
created: 2000-01-31
modified: 2000-01-31
origin: user
---
```

| 欄位 | 值 |
|---|---|
| type | profile（關於我）、preference（偏好）、skill（技能知識）、person（人）、event（事件）、area（長期領域）、project（有終點的專案）、idea（點子）、daily（日記）、moc（索引頁）、log（流水紀錄）、reference（參考資料） |
| status | active（在用）、review（待確認）、done（做完留存）、someday（也許以後）、archived（封存） |
| summary | 一句話；JDex 和搜尋都靠它，不能空 |
| created / modified | `YYYY-MM-DD`；改了內容就把 modified 改成今天 |
| origin | user（使用者親口說的）、agent-drafted（AI 草擬）、agent-inferred（AI 推測，待確認）、book（書上）、research（查資料來的）、mixed |

選填：`tags`、`aliases`、`end_date`（專案結束日）、`valid_until`（資訊過期日，過了 lint 會提醒）。

frontmatter 裡如果要放連結，整個值用引號包起來：`related: "[[21-03 線性代數]]"`，否則 YAML 會壞。

## 3. 連結與內文

- 筆記互連用 `[[檔名]]`（不含 .md）；圖片用 `![[圖.png]]`。連結目標不存在 lint 會報 ERROR。
- 一張筆記只講一件事；超過 500 行就拆。
- 待辦用 `- [ ]`，後面寫日期；太久沒處理 lint 會提醒。
- 不確定的事實寫「待確認」並把 origin 標 `agent-inferred`，不要寫成確定。

## 4. 退場 = 移到封存

- 不再用的筆記：`status: archived`，移到 `90-99 封存`。不刪。
- 封存區裡的筆記 status 一定是 archived，反過來也一樣；lint 會檢查。

## 5. 根目錄

根目錄只放 `AGENTS.md`、`CLAUDE.md`（內容只有一行 `@AGENTS.md`）、`README.md`。其他筆記都要歸到類別裡。

## 6. 自動產生與保護

| 東西 | 誰寫 | 能不能改 |
|---|---|---|
| `00 索引/00-01 JDex 索引.md` | `scripts/gen_jdex.py` 自動產生 | 不要手改 |
| 這張格式手冊、`AGENTS.md`、`CLAUDE.md` | 使用者與 AI 一起 | 改之前先問使用者 |
| `scripts/` | 這個套件 | 改之前先問使用者 |
| 其他筆記 | 都可以 | 只改要改的地方 |

## 7. 檢查

```
python scripts/vault_lint.py          # ERROR 要 0；WARN 逐條處理或說明
python scripts/gen_jdex.py            # 更新索引
```

提交時 `scripts/pre-commit` 會自動跑：阻止整份筆記被洗掉，並對要提交的內容跑 lint。
